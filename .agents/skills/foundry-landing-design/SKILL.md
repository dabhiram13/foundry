# Landing Design

Read `docs/WORKFLOW.md` first. Derive one clear audience, promise, proof sequence, and call to action from product evidence. Implement with existing components and tokens, then verify mobile layout, semantics, performance, and the real conversion path. Use `foundry work status --project PATH`, `foundry work start SLUG --spec PATH --project PATH`, and explicit `foundry work verify`/`complete` commands for scoped work. Never hand-edit `.foundry/state`.
