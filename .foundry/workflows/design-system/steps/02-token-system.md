# Step 2: Tokens

Read AGENTS.md, docs/WORKFLOW.md, the adopted product brief, and the applicable
artifact contracts before acting. Follow the actual stack, assigned write paths,
and existing authority. These steps are options for the current scope, not a
mandatory full redesign. The adopted brief overrides generic visual recipes.

Inspect the actual token system and its consumers. Define only what the adopted
direction needs: semantic color, type, spacing, dimensions, radius, motion, and
optional elevation. Reuse names and component contracts; an intentional change
needs a caller/migration plan. Use the existing stack's token representation.

Do not add gradients, shadows, color formats, or theme variables without a product
need. For each supported theme, check text/icon/control contrast and state
legibility. Keep accessible focus and reduced-motion behavior. Hand off the token
locations, changed consumers, rationale, and checks required for rendered QA.
