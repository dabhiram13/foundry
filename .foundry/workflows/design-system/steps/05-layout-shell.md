# Step 5: Layout and navigation

Read AGENTS.md, docs/WORKFLOW.md, the adopted product brief, and the applicable
artifact contracts before acting. Follow the actual stack, assigned write paths,
and existing authority. These steps are options for the current scope, not a
mandatory full redesign. The adopted brief overrides generic visual recipes.

Build the shell around the adopted flows and information architecture. Use the
actual product routes and existing navigation conventions. Sidebar, topbar,
full-bleed canvas, or content layout is a product decision, not a default template.

Make the primary task and current location clear. Exercise realistic content at
target widths; define what moves, collapses, or changes interaction. Verify mobile
controls, keyboard traversal, focus after navigation/dialogs, and relevant loading
or error transitions. Do not add an upgrade CTA or auth layout unless in scope.
Record the layout decisions, affected routes, and evidence for the next handoff.
