# Step 7: Rendered verification

Read AGENTS.md, docs/WORKFLOW.md, the adopted product brief, and the applicable
artifact contracts before acting. Follow the actual stack, assigned write paths,
and existing authority. These steps are options for the current scope, not a
mandatory full redesign. The adopted brief overrides generic visual recipes.

Inspect the project's real configured build, type, behavior, and accessibility
checks. Run relevant available checks and record command/exit/results; no automatic
palette or architecture lint is assumed. Coordinate test fixtures or ports.

Exercise changed surfaces in the running application with available browser tools:
realistic long/empty content; relevant loading/error/permission/retry states;
target widths and supported themes; keyboard access and focus recovery; labels,
contrast, zoom, and reduced motion. Save revision-linked rendered evidence within
the assigned write boundary or have the coordinator arrange capture.

Compare observed results with each adopted design/UX criterion. Record PASS,
FAIL, or UNVERIFIED with artifact/route, observation, and missing evidence. A build
alone cannot establish browser behavior. Zero relevant rendered evidence means
visual behavior is UNVERIFIED. An agent walkthrough is not customer research.

A failed repair leaves the original finding FAIL until its reproducing check
succeeds. Return findings to the coordinator; independent reviewers do not repair
or perform lifecycle transitions. The coordinator integrates authorized fixes,
settles artifact updates, and performs final runtime verification/completion.
